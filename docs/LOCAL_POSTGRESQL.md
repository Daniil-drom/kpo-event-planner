# Локальный запуск в Windows с PostgreSQL из pgsql.zip

Схема работы: браузер → Spring Boot (Java) → PostgreSQL на твоём компьютере.
Сервер PostgreSQL хранится отдельно от проекта в `D:\pgsql`; приложение открывается
по адресу `http://localhost:8080`.

В `pgsql.zip` уже находятся PostgreSQL 17 для Windows, утилиты, pgAdmin 4 и
инициализированная папка `data` с существующими базами. Для проекта создаются
собственные базы на этом же сервере:

| База | Пользователь | Назначение |
| --- | --- | --- |
| `event_planner` | `planner` | Данные приложения |
| `event_planner_test` | `planner_test` | Данные интеграционных тестов |

## 1. Подготовка PostgreSQL

Если `D:\pgsql` уже используется для лабораторных работ, используем эту установку:
повторно распаковывать архив поверх неё не нужно. База `dean_office_v5` и схема
`student_v5` не участвуют в настройке приложения.

Если такой установки ещё нет, распакуй ранее переданный `pgsql.zip` в корень
диска `D:`. Архив уже содержит верхнюю папку `pgsql`; должны получиться пути:

```text
D:\pgsql\bin\postgres.exe
D:\pgsql\bin\pg_ctl.exe
D:\pgsql\bin\psql.exe
D:\pgsql\data\PG_VERSION
D:\pgsql\data\postgresql.conf
```

Папку `data` сохраняем из этой установки. `initdb` и `scripts\initdb.bat`
запускать не требуется: кластер уже создан. В BAT-файлах исходного архива
прописан путь `C:\pgsql`, поэтому ниже используются команды с фактическим путём.

## 2. Проверка и запуск сервера БД

Открой обычный PowerShell и задай путь:

```powershell
$pgRoot = 'D:\pgsql'
& "$pgRoot\bin\pg_ctl.exe" -D "$pgRoot\data" status
```

Если сервер уже работает, переходи к проверке подключения. Если остановлен,
запусти его и дождись сообщения об успешном запуске:

```powershell
& "$pgRoot\bin\pg_ctl.exe" -D "$pgRoot\data" -l "$pgRoot\pgsql.log" -w start
```

В конфигурации из архива порт не переопределён; используется стандартный `5432`.
Проверка готовности и входа администратором:

```powershell
& "$pgRoot\bin\pg_isready.exe" -h localhost -p 5432
& "$pgRoot\bin\psql.exe" -X -h localhost -p 5432 -U postgres -d postgres -W -c "SELECT version();"
```

Ожидается `accepting connections`, затем сведения о PostgreSQL 17. `psql` запросит
пароль существующего пользователя `postgres`: используй пароль от этой установки,
с которым входил при выполнении лабораторных. Распаковка архива пароль не меняет.
При вводе пароля символы могут не отображаться.

Если открыл новое окно PowerShell, снова выполни `$pgRoot = 'D:\pgsql'`.
Если работающий сервер использует другой порт, подставь его вместо `5432` во всех
командах подключения и передай `-DbPort` скрипту приложения.

## 3. Подготовка проекта и двух баз — один раз

Распакуй новый архив проекта в локальную папку репозитория. В корне должны лежать
`pom.xml`, `README.md`, папки `src` и `scripts`. Открой PowerShell именно в этой папке.

Проверь доступность Java и Maven:

```powershell
java -version
mvn -version
```

В `pom.xml` целевая версия Java — 17; установленный JDK должен поддерживать сборку
под эту версию. Команды `java` и `mvn` должны находиться в `PATH`.
При первой сборке Maven потребуется доступ к репозиториям зависимостей.

Создай базы и пользователей:

```powershell
$pgRoot = 'D:\pgsql'
& "$pgRoot\bin\psql.exe" -X -h localhost -p 5432 -U postgres -d postgres -W -f .\scripts\create-local-databases.sql
```

Сначала введи пароль администратора `postgres`. Для новых ролей скрипт предложит
задать и повторить пароль `planner`, затем пароль `planner_test`. Сохрани их:
это отдельные учётные записи PostgreSQL, не аккаунты пользователей сайта.

При повторном выполнении существующие роли, их пароли и базы сохраняются.
Если база уже существует с другим владельцем, скрипт остановится с сообщением
`Database owner mismatch`; существующие базы автоматически не переназначаются.

Этот файл выполняется через `psql`: в нём есть команды `\password`, `\if` и
`\gexec`. Вставлять его целиком в Query Tool pgAdmin не нужно. Скрипт подготавливает
роли и базы; таблицы создаст Flyway при первом запуске приложения и тестов.

## 4. Запуск приложения

Из корня проекта выполни:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-local.ps1
```

Введи пароль `planner`. Скрипт подключит приложение к
`localhost:5432/event_planner`, соберёт JAR с модульными тестами и запустит сервер
Spring Boot. `ExecutionPolicy Bypass` действует только в запускаемом процессе
PowerShell. Пароль в файл проекта не записывается.

Дождись сообщения `Started EventPlannerApplication`. Окно оставь открытым.
При первом запуске Flyway создаст девять таблиц приложения и начальные записи
Санкт-Петербурга, Москвы и Екатеринбурга.

| Адрес | Что проверить |
| --- | --- |
| `http://localhost:8080` | Открывается интерфейс каталога |
| `http://localhost:8080/api/cities` | Возвращается JSON с тремя городами |
| `http://localhost:8080/actuator/health` | Возвращается `{"status":"UP"}` |

Загрузка KudaGo начинается фоново примерно через пять секунд после запуска.
Если каталог пуст, посмотри сообщения `Catalogue synced` или `Catalogue sync failed`
в окне приложения: доступность внешнего API проверяется отдельно от подключения БД.

При другом порте PostgreSQL или занятом порте приложения можно передать параметры,
например для БД на `5434` и сайта на `8081`:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-local.ps1 -DbPort 5434 -AppPort 8081
```

Скрипт использует работающий сервер PostgreSQL; самостоятельно его не запускает.
Файл `.env` для этого способа запуска не нужен: настройки БД передаются скриптом.

## 5. Модульные и интеграционные тесты

Из корня проекта выполни:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-local.ps1 -Test
```

Введи пароль `planner_test`. Команда выполняет `mvn verify` с отдельной базой
`event_planner_test`; тесты могут создавать и удалять в ней записи.
Рабочая база `event_planner` этим скриптом для тестов не выбирается.
Отчёты находятся в `target/surefire-reports` и `target/failsafe-reports`.

Если сервер БД работает на другом порте, передай `-DbPort` также при запуске тестов.

## 6. Остановка и повторный запуск

Приложение останавливается сочетанием `Ctrl+C` в окне запуска.
PostgreSQL продолжает работать; при следующем запуске шаг создания баз повторять
не требуется. Сохранённые данные остаются на диске.

После закрытия приложений, использующих эту БД, сервер PostgreSQL при необходимости
можно остановить отдельно:

```powershell
$pgRoot = 'D:\pgsql'
& "$pgRoot\bin\pg_ctl.exe" -D "$pgRoot\data" -m fast -w stop
```

Этот сервер общий для проекта и лабораторных: остановка отключит все его соединения.

## Если возникла ошибка

| Сообщение или ситуация | Что проверить |
| --- | --- |
| Не найден `pg_ctl.exe` или `psql.exe` | Путь `$pgRoot`; не получилась ли вложенность `D:\pgsql\pgsql` |
| `pg_ctl` не смог запустить сервер | Последние строки `D:\pgsql\pgsql.log`, доступ к папке и занятость порта |
| `Connection refused` | Запущен ли PostgreSQL, совпадает ли порт |
| `password authentication failed` | Для какого пользователя введён пароль: `postgres`, `planner` или `planner_test` |
| `mvn` или `java` не найдены | Установлены ли JDK и Maven, доступны ли они в `PATH` |
| Ошибка сборки Maven | Вывод в окне запуска; при неуспешной сборке приложение не запускается |
| Сайт работает, но мероприятий нет | Журнал фонового импорта и доступ к KudaGo |

Подготовлены команды и скрипты для такого запуска. Полный запуск на твоём Windows
с этой установкой PostgreSQL и реальную загрузку KudaGo ещё нужно подтвердить.

Docker-файлы сохранены для варианта итоговой сдачи через Compose; описанный здесь
локальный запуск от них не зависит. Сам `pgsql.zip` распаковывается отдельно от
репозитория и в архив исходников проекта не включён.

Официальная справка PostgreSQL 17:
[управление сервером pg_ctl](https://www.postgresql.org/docs/17/app-pg-ctl.html),
[выполнение SQL-файлов через psql](https://www.postgresql.org/docs/17/app-psql.html).
