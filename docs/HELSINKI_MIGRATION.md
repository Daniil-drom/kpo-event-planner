# Переход на Helsinki Linked Events — 28 октября 2026

Исходная версия: `98b4ac517745fc575a16d966e663c625ebfa7cff`, ветка
`setup/project-foundation` репозитория Daniil-drom/kpo-event-planner.

## Изменения

- KudaGoClient заменён на LinkedEventsClient. Используется публичный `/event/`
  Helsinki Linked Events без регистрации и ключа. География — Хельсинки,
  период по умолчанию — ближайшие 90 дней, обновление — раз в час.
- Пагинация `data`/`meta.next`, по 100 записей; до 200 страниц. Места и ключевые
  слова загружаются вместе с событиями через `include=location,keywords`.
  Окно дат фиксировано на весь обход; чужие URL из `next` не выполняются.
  Сортировка — по last_modified_time, start_time, name. Пересекающиеся страницы
  объединяются по ID; зацикливание без новых ID приводит к ошибке.
- Строковые ID хранятся вместе с источником. Миграция V3 сохраняет внутренние ID,
  данные KudaGo и личные планы. Старые города отключены в каталоге. V1/V2 не менялись.
- Многоязычные поля: русский, английский, финский, шведский, затем другой доступный
  язык. HTML превращается в текст. Автоматический перевод не добавлялся.
- `offers` определяет цену и бесплатность. Неизвестная цена и отсутствующее время
  окончания не заменяются выдуманными значениями. Даты без времени сохраняются
  как местный календарный день, а интерфейс показывает только дату. Часовой пояс — Europe/Helsinki.
- Родительские серии, отменённые и отложенные события скрываются. Исчезнувшие
  записи становятся неактивными только после успешного полного обновления.
  Существующие личные планы и внутренние ID сохраняются.
- Обновлены API городов, фильтры, категории, ссылки и подпись источника в интерфейсе.
  При отсутствии `info_url` ссылка ведёт на карточку tapahtumat.hel.fi.
- Ошибка HTTP теперь записывается в sync_runs с кодом ответа, например HTTP 403.
  Частичная загрузка или ошибка сохранения не заменяет прежний каталог.
- Обновлены README, инструкция локального запуска, план следующих задач и тесты.

Отдельно выполнено обновление V1/V2 → V3 на БД со старым местом, событием и

## Запуск на Windows

Распаковать исходники в новую папку. Это исключает оставшиеся от старой версии
KudaGoClient.java и KudaGoClientTest.java. Использовать уже работающую PostgreSQL
и прежнюю базу event_planner; удалять её и запускать Flyway repair не требуется.
Из корня нового проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-local.ps1
```

Ввести пароль пользователя planner, открыть http://localhost:8080.
Дождаться `Catalogue synced city=helsinki ...` и обновить каталог в браузере.
Первый импорт нескольких тысяч событий может занять несколько минут.
В консоли выводится прогресс `Linked Events download ... page=...` на первой,
каждой десятой и последней странице.
Для тестов с отдельной базой event_planner_test:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-local.ps1 -Test
```

При переносе изменений поверх существующей рабочей копии нужно удалить старые
файлы KudaGoClient.java и KudaGoClientTest.java, затем выполнить `mvn clean verify`.
Полные пути удаляемых файлов видны в патче в архиве поставки.
